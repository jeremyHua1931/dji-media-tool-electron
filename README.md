# DJI Pocket 素材筛选复制工具（Electron 跨平台版）

把大疆 Pocket 系列（或其他 DCIM 相机）拍的照片 / 视频，按日期范围与类型筛选后，
一键复制到指定文件夹。界面类似系统“文件浏览器”：支持**详细信息 / 大图标 / 中图标 /
小图标**四种视图、照片**真实缩略图**、点列头**排序**、**Ctrl/Shift 多选**、
**双击用系统默认应用打开**、右侧**预览窗格**。

> **只读相机**：本工具全程只读取相机 / 存储卡，**绝不写入、删除或修改**里面的任何文件。
> 复制前的安全检查会主动拦下"目标落在相机盘上"的操作（见
> [3.4 只读保证](#34-只读保证绝不写入相机)）。
> 用大疆 Pocket 时素材一般在 `F:\DCIM\DJI_001` 这类路径下，
> 把来源指到 `F:\` 或 `F:\DCIM` 都可以，工具默认只扫 DCIM。

技术栈：**Electron + 原生 HTML/CSS/JS（无前端框架、无运行时第三方依赖）**。
一套代码可在 Windows / macOS / Linux 上运行与打包。

界面按“结果优先”排布：打开即自动检测相机并扫描，筛选条件常驻在列表正上方，
其余设置收进可拖动、默认居中弹出的抽屉。整体为**蓝色系配色**。

要点：

- **打开即用**：启动时自动检测相机 / 读卡器，**直接定位到素材子文件夹**
  （例如 `F:\DCIM\DJI_001`，而不是让你自己进 `F:\` 里找），默认时间范围是
  **最近一天**，并**自动扫描一次**把结果列出来。
- **筛选条常驻列表上方**：
  - `文件类型`：全部（默认）/ 仅照片 / 仅视频；
  - `时间`：今天 / 一天 / 三天 / 七天 / 不限（滚动窗口，含今天），也可手填起止日期；
  - 两个复制开关：`只复制新文件`（默认开）、`复制后校验`（默认开）；
  - 右侧`已刷新 · N 个`显示最近一次扫描结果，`刷新`可立即重扫，`重置筛选`一键回到默认。
- **自动刷新**：改时间 / 改类型 / 换来源 / 收起选项抽屉后，都会**自动重新扫描**
  （内部有 650ms 合并窗口，连续点几下只会扫一次）。所以基本不需要手动点“扫描匹配文件”，
  它保留下来作为强制重扫的入口。
- **一键复制的三步流程**（与手工操作习惯一致）：
  1. 点`一键复制` → 弹出**复制选项**（同名文件策略 / 按拍摄日期建子文件夹 /
     只复制新文件 / 复制后校验 / 完成后打开目标文件夹）；
  2. 点「下一步：选择保存位置」→ 弹出系统文件夹选择框；
  3. 通过**只读保证 + 空间预检**后才真正开始复制；任一步取消都不会写任何文件。
- **弹窗一律居中**：复制选项弹窗与系统文件夹框居中；选项抽屉默认居中弹出，
  但可以按住标题栏拖到任意位置（位置记在 localStorage，窗口缩小时自动钳回可视区域）。
- **素材文件夹栏**：列出素材实际所在的文件夹路径与文件数，点“打开文件夹”用系统文件管理器打开。
- **右侧预览窗格**：缩略图 / 类型 / 拍摄时间 / 大小 / 完整路径 + `打开文件`、
  `在文件夹中显示`；多选时只做汇总。`✕` 关闭、顶栏`预览`重开，关闭后列表占满全宽。
- **点列表空白处可取消选中**：符合资源管理器习惯，也方便回到“未选 = 复制全部”。

## 典型使用流程（大疆 Pocket 为例）

1. `npm start` 打开工具，相机用 USB-C 连接并在相机屏幕选**“文件传输：USB”**；
2. 工具**自动检测**相机并直接定位到素材目录（如 `F:\DCIM\DJI_001`）——
   顶部出现绿色**只读提示**，默认按**最近一天**自动扫描并列出结果；
3. 想看别的日期就点筛选条上的`一天 / 三天 / 七天 / 不限`（或手填起止日期）——
   **改完自动重扫**，不需要再点“扫描匹配文件”；
4. 点某个文件可在右侧预览；要整体复制就直接进下一步；
5. 点`一键复制` → 先弹**复制选项**（同名策略 / 按拍摄日期建子文件夹 /
   只复制新文件 / 复制后校验 / 完成后打开目标文件夹）→ 点「下一步：选择保存位置」→
   选**电脑本地磁盘**上的目标文件夹；
   - 若目标选到了相机盘或相机目录内，会被**直接拦下**并提示原因（只读保证）；
   - 空间不足也会在开始前拦下；
6. 复制过程有进度与「取消」；完成后给出成功 / 已存在跳过 / 撞名跳过 / 改名 / 校验通过 /
   失败 的分项统计；
7. 按提示**安全弹出**相机再拔线。相机里的文件自始至终没有被修改。

> 第一次用建议先把时间调成`不限`确认素材总数，再按需要收窄；
> 想“只把新的补进去”，保持`只复制新文件`勾选即可重复运行，不会产生重复副本。
> 注意`最近一天`是按文件修改时间过滤的：老素材（几天前拍的）不会出现在默认结果里。

## 三、整体结构与逻辑

### 3.1 进程模型与安全边界

Electron 分主进程与渲染进程，本项目遵循最小权限：

- **主进程**：能访问 Node / 文件系统，负责扫描、复制、盘符检测、缩略图。
- **渲染进程**：纯网页，**不能直接用 Node**（`contextIsolation: true`、
  `nodeIntegration: false`、`sandbox: true`），只通过 `preload` 暴露的
  `window.api` 发请求。
- **IPC 侧还有三道闸**（即使渲染进程被注入脚本也无法越权）：
  1. `thumb:get` 只允许读取**本次扫描命中过的目录**里的文件，且边长必须是
     `THUMB_ALLOWED_SIZES` 白名单之一；
  2. `scan:start` / `copy:start` 的参数做类型收敛，空来源、空目标直接拒绝；
  3. `preload` 不暴露任何通用转发通道，只暴露固定的几个方法。
- 数据流：

```
界面操作(renderer)
   │  window.api.readConfig / scan / startCopy / getThumbnail / openPath
   ▼  IPC（invoke / handle）
主进程 ipc.js
   ├─ config.js    下发界面常量（缩略图/网格尺寸的单一来源）
   ├─ drives.js    检测相机盘符 / DCIM（异步枚举，不阻塞 UI）
   ├─ scanner.js   扫描并筛选（日期/类型/只扫 DCIM）
   ├─ copier.js    分块流式复制，进度经 webContents 推回界面
   └─ thumbnails.js nativeImage 出缩略图（JPEG 缓冲，经 Uint8Array 传回）
   ▼  进度事件 copy:progress / 结果
界面更新（表格/图标、素材文件夹栏、进度条、汇总）
```

### 3.2 跨平台是怎么实现的

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 盘符 / 挂载点 | PowerShell CIM 枚举 A-Z 盘（异步） | 读 `/Volumes` | 读 `/media/<用户>`、`/run/media/<用户>`、`/mnt` |
| 相机判定 | 卷根目录存在 `DCIM`（Windows 另保留可移动盘） | 同左 | 同左 |
| 系统默认打开 | Electron `shell.openPath` | 同左 | 同左 |
| 缩略图 | `nativeImage.createThumbnailFromPath` | 同左 | 同左（少数发行版支持有限，失败自动降级为占位图标） |
| 路径处理 | Node `path` 自动适配分隔符 | 同左 | 同左 |

> 相机用 USB-C 连接后，请在相机屏幕选择“文件传输：USB（U 盘模式）”，
> 相机才会以盘符 / 挂载点出现（MTP 模式无法直接读文件）。

### 3.3 复制行为

- 只复制、**绝不删除**相机里的源文件；
- 平铺或“按拍摄日期建子文件夹”（如 `2026-10-14/`）；
- 同名文件：跳过 / 覆盖 / 自动改名（`name (1).jpg`）；
- **只复制新文件**（增量）：目标里已有同名同大小的文件直接判定为“已复制过”，
  第二次运行不会重复写、也不会产生 `(1)(2)` 副本；若同名文件大小不同（例如相机里
  又拍了一张同名照片）则会重新复制；
- **复制后校验**：每个文件写完后比对目标与源的大小，不一致就删除该目标文件并计入失败；
- 1MB 分块流式复制（`stream.pipeline`，带背压），实时进度，可随时取消；
- 复制后用 `fs.utimes` 保留源文件修改时间（≈拍摄时间）。

> 关于“拍摄时间”：取的是文件修改时间（mtime）。相机直接写卡时 mtime ≈ 拍摄时刻，
> 这也是按日期筛选 / 按日期建子文件夹的依据；若素材已经被别的工具搬动过，
> mtime 可能已被改写。要按 EXIF `DateTimeOriginal` 精确排序需要额外的解析逻辑，
> 目前没有引入（保持零运行时依赖）。

实现上特别留意了几点（都有回归测试盯着）：

1. **改名必须原子**：写流以 `wx`（独占创建）打开，撞名（`EEXIST`）才换下一个编号
   重试，绝不先截断再判断——否则多个同名源文件会互相覆盖或写出 0 字节文件；
2. **取消不留残骸**：取消或失败时删掉写了一半的目标文件，避免它被下一次
   “跳过” 策略误判为“已复制成功”；
3. **校验不过不算成功**：大小不一致的目标文件会被删除并计入失败，宁可报错也不假装成功。

### 3.4 复制流程与多选规则

- 未选中任何项时，“一键复制”复制**全部**匹配结果；选中一项或多项后只复制**选中项**；
  `Ctrl+A` 全选，点列表空白处取消选中；
- 点`一键复制`后的固定三步（任何一步取消都不会写任何文件）：

  ```
  点「一键复制」
      ↓
  ┌ 复制选项弹窗（居中）───────────────────────┐
  │ 同名文件：跳过 / 覆盖 / 自动改名            │
  │ 写入方式：按拍摄日期建子文件夹 / 只复制新文件  │
  │           复制后校验 / 完成后打开目标文件夹   │
  │                        [取消] [下一步：选择保存位置] │
  └──────────────────────────────────────┘
      ↓ 确认
  系统文件夹选择框（居中）→ 选定目标
      ↓
  只读保证 + 空间预检（见 3.5）→ 通过后才开始复制
  ```

- 筛选条上的`只复制新文件`/`复制后校验`与弹窗里的同名选项**双向同步**，
  改哪边都一样；
- 抽屉里的「复制选项…」只打开这个弹窗改设置，不会触发复制流程。

### 3.5 只读保证（绝不写入相机）

这是本工具的第一原则，落到代码上是三层拦截 —— 主进程侧强制，绕不过去：

| 关卡 | 规则 | 错误码 | 为什么 |
|---|---|---|---|
| 1 | 目标目录不能落在**素材来源内部** | `DEST_INSIDE_SOURCE` | 否则复制出的文件会被下一次扫描当成素材，越复制越多（自复制递归） |
| 2 | 目标文件所在的**盘不能与源盘相同** | `DEST_SAME_VOLUME` | 相机/存储卡会以盘符或挂载点出现；写同一个盘就是在改相机内部存储 |
| 3 | 目标盘剩余空间 ≥ 待复制体积 + **安全余量**（体积的 1% 与 64MB 取大者） | `NOT_ENOUGH_SPACE` | 写到一半空间不足会留下一堆半成品，还白等半天 |

配套的其它只读措施：

- 全代码**没有任何删除源文件的路径**：只有 `createReadStream` 读源、`utimes` 写目标；
- 界面上的`在文件夹中显示`只调 `shell.showItemInFolder`，不移动/不重命名文件；
- 写入前目标目录若不存在会 `mkdir`，但**只在目标盘**（已由关卡 1、2 保证不在源盘上）；
- 「安全拔出」不在应用内代跑 `diskpart`/`eject` 之类的系统命令，只给操作指引，
  避免应用层再对相机做任何操作；
- 上面每条规则都有单元测试（含"目标在源目录内""目标与源同盘"的拦截用例）。

### 3.6 缩略图与预览

- 主进程用 `nativeImage.createThumbnailFromPath` 出图，转 JPEG Buffer 经 IPC 传回
  `Uint8Array`，渲染进程用 Blob URL 显示并在重绘时 `revoke`（避免内存与 CSP 问题，
  CSP 的 `img-src` 已放行 `blob:`）；
- 取图有并发限制（6）与负缓存（取不到的文件不反复重试）；
- **预览窗格优先取图**：点选文件后预览图会插队到队列最前，
  不必等列表里十几张缩略图依次取完；每次点选都会重新触发取图
  （只在整表重绘时排队的话，单击选中会一直停在占位图标）。

### 3.7 相机安全使用建议

1. 相机用 USB-C 连接后，在相机屏幕上选择**“文件传输：USB（U 盘模式）”**，
   相机才会以盘符 / 挂载点出现（MTP 模式无法直接读文件）；
2. 工具会自动检测并定位素材目录；也可以手动点`自动检测`或`浏览…`。
   保持“只扫描 DCIM”勾选，避免扫到相机的系统文件；
3. 目标选**电脑本地磁盘**上的文件夹（关卡 2 会强制这一点）；
4. 复制完成后按「怎么安全拔出？」的指引做**安全弹出**再拔线；
5. 建议第一次先复制少量文件核对，确认无误再整卡复制；
6. 老素材不会出现在默认的`最近一天`结果里——按需要把时间调到`三天 / 七天 / 不限`。

## 五、编译 / 打包

| 命令 | 作用 |
|---|---|
| `npm run build` | 当前系统安装包（校验 → 打包 → 自动清理中间产物） |
| `npm run build:win` | Windows：NSIS 安装程序 + 免安装 portable |
| `npm run build:mac` | macOS：`.dmg`（需在 macOS 上执行） |
| `npm run build:linux` | Linux：AppImage（需在 Linux 上执行） |
| `npm run build:dir` | 只出解包目录（最快，自测用） |
| `npm run build:export` | **一键编译 + 导出**：按平台自动选编译命令，编译后把**免安装绿色版 exe** 复制到项目根目录并加时间戳（跳过 Setup 安装向导） |
| `npm run release` | **先跑全部测试，再打包**；测试不过绝不出包 |
| `npm run release:win` 等 | 同上，指定平台 |
| `npm run test:all` | 纯逻辑测试 + 界面冒烟，一次跑完 |

额外开关（跟在 `--` 后面透传）：

```bash
npm run build -- --keep-all     # 保留解包目录、builder 调试信息等中间产物
npm run build -- --dir          # 只要解包目录
```

### 输出目录：一次编译一个时间戳文件夹

每次编译都会新建 `release/<时间戳>_<平台>/`，**历史产物不会被覆盖**，便于回退对比：

```
release/
└── 2026-10-14_2253_win/
    ├── DJI素材筛选复制工具 Setup 1.0.0.exe        ← NSIS 安装向导（可选安装目录、建桌面快捷方式）
    └── DJI素材筛选复制工具 1.0.0.exe              ← 免安装绿色单文件，双击即用
```

打包成功后会**自动删除同批次里的非必要文件**：解包目录（`win-unpacked`）、
`builder-debug.yml`、`builder-effective-config.yaml`、`.blockmap` 增量差分等，
只留下上面那两个可直接交付的安装包，并逐项打印清理内容与释放的空间。

- 想保留现场排查看中间产物，加 `--keep-all`；
- `--dir` 模式因为产物本身就是解包目录，不做清理；
- 打包**失败**时不清理，保留现场（含 `builder-debug.yml`）方便定位问题；
- 打包前脚本会先做**预检**：逐个确认 `src/**` 关键文件、`package.json` 的 `main`
  与 `node_modules/electron` 是否存在，避免做出“能启动但白屏”的包。

### 根目录一键编译导出（build.js）

项目根目录的 `build.js`（对应命令 `npm run build:export`）把「按平台选编译命令 → 编译 → 导出」合成一步：

- **按平台自动选择命令**：Windows 执行 `npm run build:win`，macOS 执行 `npm run build:mac`，Linux 执行 `npm run build:linux`，无需手动指定；
- **导出免安装版**：编译完成后，从最新一批 `release/<时间戳>_<平台>/` 中找到**免安装绿色版 exe**（文件名不含 `Setup`），复制到项目根目录并追加可读时间戳，例如
  `DJI素材筛选复制工具 1.0.0_2026-10-15_123117.exe`；
- **跳过 Setup 安装向导**：NSIS 安装程序（文件名含 `Setup`）默认**不**复制到根目录，保留在 `release` 批次目录里留档；如需连 Setup 一起导出，把 `build.js` 里的 `SKIP_SETUP` 常量改为 `false`；
- **失败保护**：编译失败时不导出任何文件、保留 `release` 现场；同批次没有可导出的安装包时明确报错。

### 为什么打包脚本分成三层进程

| 层 | 职责 | 原因 |
|---|---|---|
| `build.js`（父） | 预检、算时间戳目录、调度、汇报 | **只做纯字符串处理**，不对产物做同步 fs 调用 |
| `pack.js`（子） | 调 electron-builder 出包 | electron-builder 会加载原生模块并留下后台线程/句柄；在同一进程里等它的 Promise 结束后去删它刚写出的目录，进程会直接崩掉（Windows 上 `0xC0000409`） |
| `cleanup.js`（子） | 删中间产物、统计体积 | 本机环境下，父进程对**文件名含中文**的产物做 `fs.statSync` 会触发原生崩溃；文件系统操作隔离到子进程后，即使它崩了父进程也能如实报告“清理失败但产物可用” |

父进程的产物分类只按「扩展名 + 是否目录」判断，`--dir` 的目标用
`Platform.createTarget('dir')` 构造（直接传字符串会报 `targets is not iterable`）。

> 注意：刚打出来的免安装包（约 78 MB）可能短时间被杀软/索引进程占用，
> 此时清理会跳过它并提示 `跳过（被占用或无法删除）`——不影响该文件可用，
> 想彻底清干净可以稍后再删，或直接加 `--keep-all` 保留整批。

> 重要：Electron 应用**不能跨平台交叉编译**——
> Windows 上只能出 Windows 包；macOS 的 `.dmg` 要在 macOS 上构建，
> Linux 的 AppImage 要在 Linux 上构建。
> 推荐用 GitHub Actions 等 CI：把代码推上去后，分别在 windows / macos / linux
> 三种 runner 上执行 `npm install && npm run release`，即可得到三个平台的安装包。
